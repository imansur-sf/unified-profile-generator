# Inputs, outputs, edits and the 3D caller

## Existing internal request (not a hosted API contract)

See `examples/request-b2c.json` and `request-b2b.json` for complete local examples. The engine expects:

```json
{
  "url": "https://northstar.example/",
  "profileType": "b2c",
  "views": [
    {"lens":"sales","objective":"convert","brief":"Include call coaching and event propensity","customRole":""},
    {"lens":"service","objective":"resolve","brief":"Reschedule a family assessment","customRole":""},
    {"lens":"custom","objective":"engage","brief":"Explain modeled invoice exposure","customRole":"Finance"}
  ],
  "includeImages": false,
  "tier": "balanced",
  "projectName": "Northstar fictional demo"
}
```

`tier` is an original provider label, not a Claude model selection. Internal view IDs use `lens`; older external REST contracts used `persona`. Normalize deliberately. Default objectives are convert/resolve/engage/retain/engage for sales/service/marketing/success/custom. Validate 1–5 distinct views and require a named Custom role. Do not generate unrequested custom departments.

## Proposed skill wrapper (Claude must implement/version)

Keep the internal request above, plus a versioned wrapper with supplied brand context, scene facts, requested outputs, asset paths/provenance, output directory and overwrite policy. Example intent:

```json
{
  "schemaVersion":"upg.skill.request.v1",
  "requestFile":"request-b2c.json",
  "sourceFile":"source-b2c.json",
  "sceneFacts":[{"fact":"Family needs an evening assessment","kind":"user-supplied"}],
  "outputs":["html","json","png"],
  "canvas":{"width":1600,"height":900},
  "png":{"width":1920,"height":1080},
  "outputDirectory":"outputs/northstar",
  "overwrite":false
}
```

This wrapper is a design specification, not an already supported command. Resolve paths within the authorized workspace; reject traversal and arbitrary file reads. Validate URLs and restrict any network acquisition to approved tools/origins.

Minimum source context: URL, title, description, siteName, headings, bodyText, navLinkCandidates, logoCandidates, favicon. Optional fields may be empty; bodyText must be a string and link candidates arrays. The included `.example` sources are synthetic and must not be fetched as real websites.

## Content schema

Read `js/profile-contract.js` and emitted system/base prompts. Base responses require identity for the selected profile type; overlays skip shared identity requirements, not section validation. Sections include insights, affinities, preferences, events, membership, recommendations, activity; custom content uses extraCards/rightExtraCards/railFields. Affinity values must be finite numbers 0–100. Never infer the schema solely from these short fixtures.

Validation is necessary, not sufficient: synthetic fixtures demonstrate minimum shape, not premium personalization. Claude should fill meaningful titles, items, persona-specific facts, and appropriate screen density. Use synthetic person contact details (example domains), not falsely attributed real customer records.

## Files returned to the caller

For each persona return `<lens>.html`, `<lens>.json`, optionally `<lens>.png`, plus a shared local manifest and provenance/asset report. HTML is generated by UPG's renderer. JSON from `buildProfileArtifacts` has `schemaVersion: upg.presentation.v1`, revision, rendererVersion, persona, and **state**. It is a selected-view projection, not a complete multi-view backup.

Retain a separate versioned local multi-view project if revisions across personas are needed. The proof helper writes `project.json` as such a local wrapper; this is a helper format, not the original cloud API format.

The finished manifest should contain: skill schema version, renderer/source version, persona/profile type, revision/hash, relative file paths, image/canvas dimensions, modeled-data designation, asset readiness, missing assets, provenance path and warnings. Set PNG status to not-requested/unavailable/failed/ready truthfully. Set ready only after a valid PNG with matching content revision exists. Do not return the original hosted artifact download URLs or claim an API key is required for local files.

## Editing without calling UPG

Keep JSON authoritative: read the selected-view `.json` file's `.state`, validate it, change fields, and render again with `buildProfileArtifacts(state, {persona})`. A returned companion state intentionally lacks unrelated views. For multi-view edits, operate on the local multi-view project and select/export each affected lens. Assign approved raster assets after applying view data and refresh the appropriate snapshot.

Direct HTML edits are possible on a local copy, but subsequent JSON rendering overwrites them. Any edit requires new revision metadata and recapture to update the PNG. An existing PNG cannot change itself when HTML changes. Never claim local edits save back to UPG.

## Presentation composition

The 3D skill provides a request + scene brief and consumes local artifacts through a manifest. This is a file/script contract, not a promise that one installed skill can automatically invoke another. Verify actual orchestration in the intended Claude product. Place PNG at 16:9 without stretching; if no PNG runtime exists, return HTML/JSON and explain the missing capability. Interactive HTML embedding depends on the caller's security and execution model. Do not publish local machine paths, credentials or private source URLs.
